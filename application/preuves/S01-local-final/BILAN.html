Résultats : 168 contrôles réussis

  • 102 tests unitaires sous Linux/Python 3.13.17 avec cryptography 50.0.2 : sessions chiffrées, concurrence, crashs, droits, contrôles de santé et worker.
  • 12 contrôles sur Supabase local : accès autorisés et refusés, paramètres d’organisation falsifiés, ressources étrangères et RLS directe.
  • 9 contrôles HTTP : session, cookie, CSRF/origine, lecture, déconnexion et refus ultérieur.
  • 45 contrôles de récupération MFA sur restauration isolée : approbation distincte, annulation, refus sans autorisation, anti-rejeu, remplacement du facteur et maintien du cloisonnement.
  • 834 empreintes de référence inchangées ; frontières des modules et 14 migrations de référence vérifiées.

Le banc Linux tourne sans réseau, sous utilisateur non privilégié, avec code en lecture seule ; les répertoires privés ne sont pas montés. La récupération utilise une clé propre à la cible isolée. Les facteurs MFA source ne sont pas modifiés.

Finalisé dans ce lot

Un contrôle qualité exécutable localement est ajouté : scripts/local_quality.py. Le lanceur scripts/linux_quality.py exécute le même contrôle dans l’image construite avec docker build -t uniion-quality:local -f ci/Dockerfile ci. Le lanceur nécessite Docker dans PATH. La construction installe la dépendance depuis le registre ; les tests eux-mêmes fonctionnent sans réseau. L’image de base est une étiquette locale à figer par digest pour une future chaîne de livraison reproductible.

Ces tests qualifient les composants sous Linux ; ils ne simulent pas un VPS complet, plusieurs instances ou un déploiement de production. Le workflow distant reste un modèle inactif.

Réserves S01 restantes

  1. Activer et tester le transport privilégié du worker sur la pile source : aucune configuration dédiée n’est actuellement fournie. Le moteur de récupération et l’API Auth ont été testés sur une cible restaurée isolée ; cela ne vaut pas activation du worker source.
  2. Automatiser le provisionnement d’une pile Supabase entièrement éphémère pour la CI. Les intégrations exécutées ici utilisent la pile locale et, pour la récupération, sa restauration isolée ; le contrôle Linux unitaire n’est pas une intégration Supabase complète.
  3. Lors de la préparation du déploiement : qualification du serveur Linux complet, HTTPS, origines, sessions en topologie cible, secrets, environnements distincts et CI distante. Ces points restent différés à la demande du propriétaire.

Aucun défaut révélé par les contrôles exécutés. S01 reste ouvert pour ces réserves ; ne pas confondre succès des tests et livraison de l’application entière.
