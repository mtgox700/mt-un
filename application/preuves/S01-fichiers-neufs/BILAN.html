S01 · Fichiers réels sur pile neuve

26 octobre 2026 — 163 contrôles réussis : 102 tests Linux et 61 contrôles d’intégration, dont 21 contrôles ajoutés pour les fichiers.

Validé

  • Envoi réel d’un PNG et d’un PDF dans Storage privé, analyse ClamAV réelle, contrôle de format par moteur isolé.
  • Téléchargement propriétaire : octets strictement identiques aux originaux.
  • Aperçus réels image et PDF générés en PNG ; artefacts inspectés. Fixtures minimales : image 2 × 2 pixels et PDF blanc d’une page. Cela valide le moteur, pas une mise en page métier.
  • Partage explicite avec téléchargement : refus sans permission locale du destinataire, succès après attribution explicite sur le compte fictif, aperçu autorisé.
  • Refus d’accès étrangers, d’écriture étrangère, d’écrasement et de lecture directe Storage par le propriétaire.
  • Après révocation du partage : aperçu et téléchargement refusés.
  • Fichier standard de test EICAR détecté infecté par ClamAV ; conservation en quarantaine et téléchargement refusé.

Correction effectuée

La base vide ne disposait pas des droits d’infrastructure nécessaires sur le schéma Storage. Le provisionnement CI les initialise désormais. Les autorisations de tables restent soumises aux politiques RLS : aucune ouverture de lecture directe et aucun changement des règles métier. Le refus sans permission locale de téléchargement était correct ; le jeu de test a été complété pour vérifier les deux cas.

Prototype et S00 inchangés : 834 empreintes vérifiées. Aucun compte, secret ou contenu de la pile source n’est utilisé. Les fonctions de la passerelle de référence sont importées en lecture seule ; leur transport est raccordé à la cible neuve et l’identité scanner est créée uniquement dans celle-ci. Le moteur antivirus local et l’image locale de rendu sont utilisés.

Reste à faire

  1. Porter la récupération MFA complète sur les fixtures de base neuve. Le transport réel est déjà validé séparément sur restauration isolée.
  2. Activer le worker MFA sur la pile source lorsque sa configuration dédiée sera disponible.
  3. Intégrer la passerelle de fichiers dans les modules définitifs de l’application : ce lot qualifie le comportement de référence, il ne constitue pas encore son portage complet.
  4. Poursuivre le frontal fidèle, le hors-ligne sécurisé et la synchronisation, puis la recette visuelle mobile/tablette/desktop. Aucun écran n’a été changé ou retesté visuellement ici.

La réserve « vrais fichiers / antivirus / aperçu / téléchargement sur pile neuve » est levée pour ces scénarios. S01 conserve les autres réserves. Aucun déploiement ni suppression automatique ; conteneurs de test arrêtés et volumes conservés.
