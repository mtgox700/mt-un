S03 — Agenda : premier lot local

27 octobre 2026 · Lot initial testé — sprint non clôturé.

Réalisé

  • Lecture, création et modification réelles dans Supabase local, depuis les écrans Agenda existants.
  • État et service Agenda isolés dans leur module frontal. Les événements de démonstration sont retirés de cet écran en mode authentifié.
  • Session MFA, organisation active, adhésion, droit commercial, activation du module et permissions vérifiés côté base à chaque commande.
  • Audiences explicites par utilisateur et organisation : aucun accès implicite entre organisations, aucun contournement métier pour le super admin. Pas de publication anonyme ni de propagation vers l’intranet.
  • Tables privées, RLS activée, aucun accès direct pour anon/authenticated ; seules les fonctions contrôlées sont exécutables.
  • Version optimiste pour refuser les écrasements concurrents ; journal de modification sans contenu métier.
  • Aucune suppression effectuée. Le bouton signale le circuit d’approbation encore à construire.
  • Préférence de rappel conservée, sans prétendre qu’un courriel a été envoyé. Convocation, ordre du jour et export ICS signalés comme non raccordés dans le mode réel.

Preuves

  • 25 contrôles d’intégration réussis : MFA, création/lecture/édition, audiences, organisation étrangère, droits insuffisants, module désactivé/impayé, adhésion révoquée, version périmée, champs indus et table inaccessible.
  • Recette interface : création autorisée aux formats 390 × 844, 768 × 1024 et 1440 × 1000 ; lecture filtrée et modification refusée aux trois formats ; modification sur mobile et persistance après rechargement vérifiées.
  • 113 tests Python existants réussis ; 22 suites frontales réussies, dont le nouveau service Agenda ; compilation réussie.
  • 834 empreintes protégées inchangées : prototype et S00 intacts. Aucun fichier de style ni gabarit de l’interface modifié.

Les dimensions sont émulées dans le navigateur local ; ce ne sont pas des essais sur appareils physiques. Aucun débordement horizontal mesuré. La recette ne couvre pas encore tous les scénarios S03.

Reste à faire pour S03

  1. Terminer l’extraction des vues, des préparateurs et des actions Agenda encore dans le contrôleur commun ; contractualiser les contributions à l’accueil, dont les échéances sont encore de démonstration.
  2. Administrer les audiences depuis l’interface avec des permissions dédiées et un vocabulaire cohérent selon le type d’organisation. Pour cette recette, les audiences ont été affectées uniquement aux comptes fictifs par préparation SQL.
  3. Raccorder les rappels à une file durable et tester délais, fuseaux horaires, reprise et non-duplication des envois. Actuellement, seule la préférence est sauvegardée.
  4. Raccorder export ICS avec droit de téléchargement, convocations et ordre du jour via les contrats de leurs modules ; valider séparément toute diffusion vers les espaces adhérents/intranet.
  5. Construire la demande de suppression et la validation super admin, puis tester leur traçabilité. Aucun endpoint de suppression Agenda n’est disponible.
  6. Tester migration sur pile vierge, sauvegarde/restauration de ces nouvelles tables, dépendances du module, désactivation/réactivation et reprise.
  7. Compléter la recette visuelle : les notifications héritées peuvent recouvrir temporairement un bouton sur petit écran (capture ci-dessous). Les champs mobiles dépassent légèrement le bord intérieur de la carte sans débordement de page. Ces points n’ont pas été retouchés dans ce lot pour respecter la demande de conserver la présentation.
